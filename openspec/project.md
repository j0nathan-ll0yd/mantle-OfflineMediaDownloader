# Project: OfflineMediaDownloader backend (mantle-OfflineMediaDownloader)

> **OpenSpec adoption (2026-07-01).** This `openspec/` directory is the curated behavioral-contract
> layer for the OMD backend, following the pattern proven on LifegamesPortal (PR #114). Density
> is 4a: ~5-6 CORE specs covering the deepest, silent-and-untested invariants, plus 3 tethered
> tests (cascade-deletion ordering, authorizer verify-before-handler, push endpoint-cleanup-on-
> invalid-token). The open question — _do these specs stay fresh under real change?_ — is evaluated
> continuously; the `check-openspec-behavior-only.sh` fence catches restated schema shapes. See
> `.omc/plans/openspec-monorepo-adoption.md` for the full design rationale.

## Mantle framework governance (READ FIRST — how this project works)

This backend is a **Mantle framework** application. **Mantle is the framework** (developed at
`~/Repositories/mantle`); it governs the entire build/deploy/codegen/convention lifecycle. OpenSpec
specs describe capability BEHAVIOR layered on top of Mantle — they never override the framework.
When a spec and a Mantle convention appear to conflict, **the Mantle convention wins.**

- **The `mantle` CLI is the only supported entry point** — `mantle build` / `mantle deploy --stage
<stage>` / `mantle generate` (infra, openapi, permissions) / `mantle db` (generate, migrate) /
  `mantle check` (conventions) / `mantle ci`. Never invoke raw esbuild / tofu / drizzle-kit directly
  (B3).
- **Infrastructure is generated, never hand-written** — `mantle generate infra` emits all `.tf` from
  `mantle.config.ts` (C67). Never create `.tf` files by hand.
- **Handlers are factory-defined** — every Lambda uses a `define*Handler` factory from
  `@mantleframework/core` or `@mantleframework/validation`. No class handlers, no middy. The custom
  authorizer is the sole entry point for API auth (C7/C75/C76).
- **Events via `emitEvent`/`emitEvents`** (always awaited — C34/C58); **DB via `defineQuery`** with
  per-query table permissions (C10/C30/C39); **env via `getRequiredEnv`/`getOptionalEnv`** (C6;
  MigrateDSQL has a documented exception at `src/lambdas/standalone/MigrateDSQL/index.ts:44`).
- **Conventions (C1–C143) are enforced by `mantle check`** + the agent-enforcement ruleset — not by
  these specs. The framework's authoritative range governs; AGENTS.md, CLAUDE.md, and README.md defer
  to it. These specs assume the Mantle programming model throughout.

## Authority hierarchy (READ FIRST)

1. **`AGENTS.md`** (this repo's real governance anchor; `CLAUDE.md` passes through with `@AGENTS.md`)
   - the agent-enforcement Mantle rules **(C1–C143)** are the AUTHORITATIVE convention layer.
     OpenSpec does NOT replace them. `openspec init` does not modify `AGENTS.md` or `CLAUDE.md`.
2. **Generated machine contracts own STRUCTURE, not OpenSpec:** `docs/api/openapi.yaml` (generated by
   `mantle generate openapi` / `pnpm run generate:openapi`), `src/types/api-schema/` (Zod schemas,
   source of truth for request/response shapes), `graphrag/metadata.json` + `build/graph.json`
   (GraphRAG knowledge graph, CI-gated). These machine tiers are the single source of truth for
   structure. **OpenSpec specs MUST NOT restate field-level shapes owned here** — they describe
   BEHAVIOR/INVARIANTS only. Restating a Zod field set is a boundary violation (see
   `scripts/check-openspec-behavior-only.sh`).
3. **`openspec/specs/`** = living BEHAVIORAL contracts (what a capability does, in RFC-2119
   SHALL/MUST + GIVEN/WHEN/THEN scenarios), sitting ABOVE the machine tiers. `openspec/changes/` =
   in-flight proposals via the `/opsx:propose → /opsx:apply → /opsx:archive` workflow.

## What this is

OfflineMediaDownloader backend — AWS serverless media pipeline. TypeScript on the Mantle framework,
18 AWS Lambda functions, Aurora DSQL + Drizzle. Downloads media (primarily YouTube via yt-dlp with
cookie auth), stores to S3, notifies iOS companions via APNs, integrates Feedly webhooks, and
manages device/file lifecycle. Companion iOS app (`ios-OfflineMediaDownloader`) is the sole consumer.

## Tech stack

Mantle framework · Node 24 ESM · TypeScript strict · Aurora DSQL + Drizzle · Zod validation ·
EventBridge + SQS · APNs · pnpm.

## Architecture invariants (behavior, not shapes)

- **iOS is the sole consumer.** All API endpoints are designed for the companion iOS app;
  there is no web frontend.
- **OMD backend is the sole producer** of `docs/api/openapi.yaml` and syncs it to
  `ios-OfflineMediaDownloader/APITypes/Sources/APITypes/openapi.yaml` via
  `Scripts/sync-openapi.sh`. No other service writes OpenAPI for this iOS contract.
- **Vendor encapsulation is absolute.** All AWS SDK and third-party library access MUST go through
  `#lib/vendor/*` wrappers. Raw imports from `@aws-sdk/*`, `drizzle-orm`, etc. are forbidden and
  caught by `mantle check` (C-raw-aws-sdk). Specs describe behavior ABOVE these wrappers; they never
  reference the underlying SDK types.
- **Cascade deletions are children-first with `Promise.allSettled` isolation.** Deleting a parent
  entity (user) MUST delete all child entities (files, devices, relationships) before removing the
  parent. `Promise.all` for cascade chains is forbidden (mantle check: cascade-safety). Partial
  child failures are isolated; they never silently leave an inconsistent parent.
- **Custom authorizer is the API access gate.** The `ApiGatewayAuthorizer` Lambda verifies all
  non-Feedly API requests (Sign In With Apple + Better Auth session tokens) before any handler runs.
  The Feedly webhook uses query-parameter auth via its own authorizer path.
- **All `.tf` is generated** by `mantle generate infra` (C67) — never hand-written.

## iOS cross-repo contract

OMD backend is the **sole producer** of the iOS API contract. When specs describe API behavior,
they describe what the iOS client receives — not internal AWS routing. Any change to the OpenAPI
shape MUST:

1. Run `pnpm run generate:openapi` to regenerate `docs/api/openapi.yaml`.
2. Sync to `ios-OfflineMediaDownloader` via `Scripts/sync-openapi.sh`.
3. Update the iOS `APITypes` package accordingly.

Specs in `openspec/specs/cross-repo-contract/` document this boundary's behavioral invariants
(additive-only evolution, versioning rules). The structural contract itself lives in
`docs/api/openapi.yaml` — not here.

## OMD-specific spec fences (what specs MUST NOT do)

These apply across all specs in this project and are mechanically checked by
`scripts/check-openspec-behavior-only.sh`:

- **No Zod shape restatement.** Zod schemas at `src/types/api-schema/` own all field-level shapes.
  Specs cite them (`Source of truth: src/types/api-schema/FileSchemas.ts`) and describe behavioral
  invariants only; they do NOT restate field lists.
- **No raw AWS SDK references.** Specs describe behavior above `#lib/vendor/AWS/*`. Never reference
  `@aws-sdk/*` types, `S3Client`, `SNSClient`, etc. in a spec. Reference the vendor wrapper's
  semantic contract instead.
- **No OpenAPI field restatement.** `docs/api/openapi.yaml` is the machine-tier source of truth for
  response shapes. Specs cite it; they do not duplicate its field lists.
- **No GraphRAG metadata restatement.** `graphrag/metadata.json` and `build/graph.json` own
  Lambda dependency structure. Specs describe behavioral invariants, not wiring topology.

## Entity-query mocking convention

Tests derived from these specs mock entity queries via `vi.mock('#entities/queries')` — never the
legacy `vi.mock('#entities/Users')` etc. pattern. All mock implementations use the factory functions
in `test/helpers/entity-fixtures.ts` and AWS SDK mocks from `test/helpers/aws-sdk-mock.ts`.

## `covers:` convention for tethered tests

Specs that have tethered tests use the provisional annotation format:

```text
// covers: <capability>#<requirement-name>
```

placed as a comment at the top of the covering test file or test block. Example:

```typescript
// covers: cascade-deletion#children-deleted-before-parent
```

**Scope-match rule:** a requirement may claim ONLY what its covering test actually asserts;
broader behavior belongs in untethered requirements or prose. A `covers:` badge on a test that
asserts less than the requirement claims is net-negative — the tether signals existence, not
correctness; authoring review is the semantic backstop.

**Multi-test labeling:** when multiple tests share a single requirement (as
`cascade-deletion#children-deleted-before-parent` does after the B3 iteration), each `verified by`
citation MUST include a parenthetical scope label identifying what that specific test asserts —
e.g., `test/path.test.ts (endpoint cleanup ordering)`.

The framework lane is building a `mantle check openspec` drift-tether gate (Workstream A). Once
that gate is live, the `covers:` format may be finalized. Adjust annotations when the team-lead
broadcasts the final format. Until then, the provisional format is the canonical form.
